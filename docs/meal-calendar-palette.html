Past days go fully grey — dates and bars — because they're history, not choices. Staged edits use a dashed bar and a bright • on the cell, so an unsaved calendar is visibly unsaved from across the room. Nothing writes to the backend until enter.

Save confirmation

  ━━ ━│                                        │─ ──
       │  thu 13 aug  ·  cutoff 21:00, 6h 12m left  │
  17   │                                        │       22     23
  ━━ ━│  +  ━━  lunch      beef tehari          │─ ──
       │  −  ━━  snacks     shingara·cha         │
  24   │                                        │       29     30
  ━━ ─│     enter save        esc cancel         │━
       └────────────────────────────────────────┘

The modal is the one place a drawn border earns its keep — it has to visibly float above a grid that's still partly visible behind it. It shows a diff, not a restatement: only what changes, signed + and −, with the cutoff time right there because that's the fact that makes the decision urgent. enter commits, esc returns you to the staged state without losing it.

Delete

Two different operations, and they deserve different weight. Turning one meal off is an ordinary staged edit — the ╌╌ state above, reversible, folded into the same save. Clearing a whole day is destructive and immediate, so it gets its own confirm and its own key.

  ┌ delete all meals ──────────────────────┐
  │                                       │
  │  thu 13 aug — 3 booked meals          │
  │                                       │
  │  ━━ breakfast   ━━ lunch   ━━ snacks  │
  │                                       │
  │  after 21:00 this cannot be undone    │
  │                                       │
  │      y  delete        esc keep        │
  └───────────────────────────────────────┘

Destructive confirm takes y, not enter — so muscle memory from the save dialog can't wipe a day. Red appears here and nowhere else in the app, which is what makes it mean something. It shows what will be lost rather than asking "are you sure": three named meals is information, a yes/no question isn't.

Key hints

  scope    today   tomorrow   week 

  ━━  breakfast      ┄┄  lunch      ╌╌  snacks

  delete day   quit   enter save   esc discard

The hint character sits inside the word itself in cool blue — the one hue no meal claimed, so it reads instantly as interface chrome rather than food. No brackets, no separate keybinding legend to maintain.

The collision is the interesting part. today and tomorrow both start with t. btop's answer is to highlight whichever character is unique, so tomorrow becomes tomorrow. Don't pick o — the second letter of both words is also the same, and a hint that requires the user to count characters isn't a hint. Reach for the first consonant that's actually free.

On the active item, blue-on-bright-background would fail contrast, so the hint switches channel: dark text, underlined. Same information, no unreadable pairing.

Full map, all free of each other: t today · m tomorrow · w week · b l s toggle one meal · B L S toggle a meal across the whole week · d delete day · enter save · esc discard · q quit. Note this retires the earlier g-for-today binding — with t jumping to today's scope, a second "go to today" key is redundant.
